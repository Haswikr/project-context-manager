# 项目专属规则 / RULES

## 写作
- 遵循 anti-defensive-writing：直接提出结论、事实、依据、机制；保留真正改变结论有效性或使用边界的限定。
- 避免惯用“并非……而是……”“需要强调的是……”“值得注意的是……”等防御性套话。
- 一段一项任务；普通回答简洁，技术推导提供必要公式与假设。

## 证据与验证
- 将信息分为：已核验事实、理论推导、合理假设、待核验事项。
- 给出可核查来源：文件路径、版本、页码/公式号、数据日期或链接。
- 未验证结果不升格为已证实创新或实验事实；遇到冲突直接指出并处理。

## 一致性与文件维护
- 当前最新用户决策优先。每次关键变更记入 `02_DECISIONS.md`。
- `05_SNAPSHOT.md` 只表示当前状态，长篇原始成果放入源文件。
- 更新快照前保留旧版到 `snapshots/`；无法写入时清楚标注未保存。
- 使用 `/对齐`、`/快照`、`/交接`、`/指令`；每次项目管理答复附相关指令。
